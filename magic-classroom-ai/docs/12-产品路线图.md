# Magic Classroom AI — 产品路线图

## 阶段 A：4 小时 Scene01 Demo
目标：完成高质量开场动画，验证视觉方向和技术路线。

交付：
- IntroScene
- 原创导师
- 英国地图
- Start Journey
- 粒子/轻量动画
- 声音/全屏/目录
- 可部署 Web 链接

成功标准：领导可顺畅打开并完成开场体验。

## 阶段 B：1~2 周完整领导 Demo
目标：形成一条完整学习链路。

交付：
- 8 个场景模板基础版
- Britain 示例课程 JSON
- 基础进度和奖励
- Demo 静态部署
- 演示脚本和备用离线版本

成功标准：从开场到结果页完整走通，并证明与 PPT 的体验差异。

## 阶段 C：2~6 周产品化 MVP
目标：从一次性 Demo 升级成教师可使用产品。

交付：
- 登录/RBAC
- 课程管理
- 场景编辑器
- 模板系统
- 素材上传
- CourseVersion
- 预览/发布
- 基础学习 Session
- 基础统计

成功标准：教师不改代码即可创建和发布课程。

## 阶段 D：AI 课程生成
目标：显著降低课程制作成本。

交付：
- 教材上传
- 内容解析
- 知识点提取
- Scene Planner
- Course JSON 生成
- Schema 校验
- 教师 Review
- Prompt 版本与成本记录

成功标准：教师从教材到可编辑课程草稿的时间显著减少。

## 阶段 E：单校正式试点
目标：验证真实教学使用。

重点：
- 稳定性
- 教师工作流
- 学生完成率
- 课程制作耗时
- 模板复用率
- AI 生成准确性

不要仅看注册人数，要观察真实活跃和课堂使用。

## 阶段 F：多学校 SaaS
交付：
- 多租户
- 学校管理员
- 配额
- 统一模板市场/素材库
- 成本与审计
- 高可用部署
- 更完整统计

## 阶段 G：多学科
在模板引擎成熟后扩展：
- 英语
- 历史
- 地理
- 生物
- 数学
- 化学

策略：先抽象跨学科组件，再针对真正不同的教学行为增加模板。

## 阶段 H：平台化
可能方向：
- 校级品牌定制
- 教研协作
- 模板市场
- AI 教师助手
- 课程质量评估
- 国际化

## 核心指标
### Demo
演示稳定率、完成率、领导/教师反馈。

### MVP
课程创建数、发布率、平均制作时长、模板复用率。

### AI
AI 草稿采纳率、人工修改量、生成失败率、单课生成成本。

### SaaS
学校活跃数、教师周活、学生学习完成率、课程复用、基础设施成本。

## 决策原则
1. 任何新功能先证明能提高教学价值或生产效率。
2. 不因“看起来高级”提前引入复杂基础设施。
3. 先让第二门课程比第一门明显更快制作。
4. 如果每门课程仍需大量手改 React，说明模板化未完成。
