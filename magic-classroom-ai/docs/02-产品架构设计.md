# Magic Classroom AI — 产品架构设计

## 1. 产品总体结构
Magic Classroom AI 分为三个主要产品面：

1. 学生端 Course Player
2. 教师端 Course Studio
3. 平台/学校管理端 Admin Console

长期目标是形成“内容输入 → AI 生成 → 教师编辑 → 发布 → 学习 → 数据反馈”的完整闭环。

## 2. 学生端
### 核心模块
- 课程首页
- 场景播放器
- 互动任务
- AI 导师
- 学习进度
- 奖励/金币/徽章
- 课程总结
- 学习结果

### 核心路径
打开课程 → 开场动画 → 学习场景 → 互动任务 → 总结 → 完成页。

## 3. 教师端
### 我的课程
- 草稿
- 已发布
- 已归档
- 复制课程
- 删除课程

### 课程编辑器
推荐三栏布局：
- 左：场景列表
- 中：实时预览
- 右：属性配置

支持：
- 新增/删除/排序场景
- 替换模板
- 修改文本
- 上传素材
- 配置互动
- 预览
- 保存草稿
- 发布

### AI 生成
- 上传教材或粘贴内容
- 选择年级/课程类型
- AI 解析
- 生成大纲
- 生成场景
- 教师审核
- 一键生成课程草稿

## 4. 学校管理端
- 教师管理
- 班级/学生管理（第二阶段）
- 课程统计
- 资源配额
- 校内模板
- 学校品牌配置

## 5. 平台管理端
- 学校/租户管理
- 模板管理
- 公共素材库
- AI Provider 管理
- Prompt 版本管理
- 使用量统计
- 审计日志
- 系统配置

## 6. 内容生产架构
```text
教材/教案/文本
      ↓
内容解析
      ↓
知识点结构化
      ↓
课程规划
      ↓
Scene Planner
      ↓
Template Matching
      ↓
Course JSON
      ↓
教师 Review
      ↓
素材补充
      ↓
发布版本
```

## 7. 模板体系
第一批模板：
- Intro
- Map Explore
- Timeline
- Reading
- Quiz
- Matching
- Summary
- Result

后续可扩展：
- Dialogue
- Flashcard
- Sorting
- Drag-and-drop
- Virtual Lab
- Image Hotspot
- Branching Story

模板负责交互形式，课程 JSON 负责具体教学内容。

## 8. 课程生命周期
- draft：草稿
- validating：校验中
- ready：可发布
- published：已发布
- archived：已归档

已发布课程使用 CourseVersion 固化，后续编辑产生新版本。

## 9. 权限体系
### Student
仅学习和查看本人结果。

### Teacher
创建、编辑、预览、发布自己的课程。

### School Admin
管理本校教师、课程、资源和统计。

### Platform Admin
平台级配置和租户管理。

## 10. Demo 与正式产品关系
Demo 不做独立一次性页面。

Demo 的 Scene01、地图、时间轴等必须直接使用正式 Template 架构，以便领导认可后继续扩展。

## 11. 批量生产模型
未来新增课程时：
- 不重新复制 React 页面。
- 新增/生成 CourseConfig。
- 复用模板。
- 只为真正新的教学交互新增模板。

这样第二门课的成本主要来自内容审核和素材，而不是重新开发前端。

## 12. 首个示范课程
Magic Journey · Explore Britain 作为产品 reference course，用于：
- 展示视觉上限
- 验证模板能力
- 验证 JSON Schema
- 验证大屏体验
- 验证第二门课程复用效率

## 13. 商业化基础能力
产品化后至少具备：
- 多学校租户
- 课程权限
- 发布链接
- 数据统计
- AI 生成配额
- 存储配额
- 模板版本
- 日志与备份

## 14. 不建议过早建设
在没有真实学校使用前，不优先：
- 微服务拆分
- K8s
- 复杂实时协作
- 大型 3D 引擎
- 超细粒度 BI
- 自研基础设施

优先确保课程生产效率和课堂体验。
