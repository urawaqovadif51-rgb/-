# Magic Classroom AI（魔法课堂）产品需求文档 PRD

> 版本：V1.0
> 状态：Demo → 产品化基础版
> 首个示范课程：Magic Journey · Explore Britain

## 1. 产品定义
Magic Classroom AI 是面向学校、教师和学生的 AI 沉浸式互动数字课程平台。系统的长期目标是将教材、教案或结构化教学内容转换为可交互、游戏化、可复用的网页课程，并通过模板系统降低批量课程生产成本。

第一阶段不追求一次完成完整 SaaS，而是完成一套能向学校领导演示产品价值、同时可以继续产品化的可运行 Demo。

## 2. 核心价值
1. 将静态教材转为互动数字课程。
2. 用 AI 辅助课程内容结构化、场景拆分和素材生产。
3. 通过课程模板 + JSON 配置实现批量生产，而不是逐页重复开发。
4. 支持 PC、教学大屏和平板，后续扩展移动端。
5. 为教师提供低门槛课程生成、编辑、预览和发布能力。

## 3. 用户角色
### 3.1 学生
进入课程、完成互动任务、查看进度、获得奖励和学习反馈。

### 3.2 教师
创建课程、上传教材、编辑 AI 生成结果、预览、发布、查看学习数据。

### 3.3 学校管理员
管理教师、课程、模板、学校资源与使用情况。

### 3.4 平台管理员
管理模板、AI 模型配置、公共素材、租户、系统监控与内容审核策略。

## 4. 产品阶段
### Phase 1：领导演示 Demo
目标：快速证明沉浸式数字教材体验。
- 完成首个英国主题示范课程。
- 序号1“开场动画”为最高优先级。
- 不强制真实后台，课程可先读取本地 JSON。
- 部署为可分享 Web 页面。

### Phase 2：产品化 MVP
- 用户登录与角色权限。
- 课程管理。
- 模板管理。
- 素材上传与对象存储。
- JSON 驱动课程播放器。
- 教师编辑和发布。

### Phase 3：AI 课程生成
- 上传教材。
- 文本解析与章节识别。
- AI 生成课程结构。
- 推荐互动模板。
- 生成课程 JSON 草稿。
- 教师审核后发布。

### Phase 4：规模化 SaaS
多学校/租户、统计分析、资源配额、审计、弹性扩容、CDN、AI 成本控制。

## 5. Demo 信息架构
- Scene 01：Magic Journey 开场动画
- Scene 02：英国地图探索
- Scene 03：历史/文化时间轴
- Scene 04：阅读互动
- Scene 05：游戏化任务
- Scene 06：AI 导师问答（Demo 可模拟）
- Scene 07：知识总结
- Scene 08：学习结果与奖励

## 6. Scene 01：开场动画（P0）
### 6.1 目标
在 10~20 秒内建立产品第一印象，并让用户明确知道课程主题和下一步操作。

### 6.2 视觉结构
- 16:9 主画布，优先适配 1920×1080 教学大屏。
- 魔法学院/奇幻英国主题夜景，但不得直接复制受版权保护影视作品的具体美术资产或角色形象。
- 左侧：主标题、副标题、简短欢迎文案。
- 中部：原创 AI 魔法导师角色。
- 右侧：英国地图视觉元素。
- 右侧悬浮工具栏：目录、声音、全屏。
- 底部或视觉中心：Start Journey 主按钮。

### 6.3 动画
P0：页面淡入、标题入场、导师轻微漂浮、地图节点呼吸、按钮发光、背景粒子。
P1：云层移动、光效层、地图区域 hover。
P2：猫头鹰等装饰动画、复杂魔法棒粒子、视差。

### 6.4 交互
- Start Journey：进入 Scene 02。
- 声音：开启/关闭 BGM，并记住当前会话状态。
- 全屏：调用浏览器 Fullscreen API；失败时优雅降级。
- 目录：打开场景目录面板。
- 地图区域：hover 高亮；Demo 可不承担主要导航。

### 6.5 音频规则
浏览器通常限制未经过用户操作的自动播放。实现时不得依赖强制 autoplay；首次用户交互后再启动音频，并提供明显的静音控制。

### 6.6 Scene 01 验收
- 1920×1080 无明显布局错误。
- 1366×768 可正常展示。
- 页面加载失败时有资源降级，不出现白屏。
- Start Journey 可进入下一场景。
- 声音和全屏按钮可工作。
- 动画不阻塞主要操作。
- prefers-reduced-motion 用户可以降低动画。
- 首屏资源经过压缩，避免无必要的大体积图片/视频。

## 7. 课程播放器
统一 CoursePlayer 根据课程配置渲染场景。

核心能力：
- 读取 CourseConfig。
- 根据 scene.type 映射模板组件。
- 管理 currentScene、progress、score、reward、audio。
- 场景前进/后退。
- 保存学习会话（MVP 可 localStorage，正式版同步服务器）。
- 异常场景 fallback。

## 8. 模板系统
首批模板类型建议：intro、map-explore、timeline、reading、quiz、matching、summary、result。

原则：课程文本、素材 URL、热点、问题、答案、奖励等不得硬编码在 React 页面里；模板读取 JSON 配置。

## 9. 教师端 MVP
- 登录。
- 我的课程。
- 新建课程。
- 课程基础信息编辑。
- 场景列表排序。
- 场景配置编辑。
- 素材上传/替换。
- 预览。
- 发布/取消发布。
- 复制课程。

## 10. AI 生成工作流
教师上传内容 → 文档解析 → AI 生成课程大纲 → 场景规划 → 模板匹配 → 课程 JSON → 教师审核/编辑 → 资源生成或上传 → 校验 → 发布。

AI 结果必须视为草稿；教师能够修改后再发布。生成链路应保存 prompt/version/model/状态，便于重试和追踪。

## 11. 数据对象
主要实体：User、School/Tenant、Course、CourseVersion、Scene、Asset、Template、GenerationJob、LearningSession、InteractionRecord、Reward。

正式数据库优先 PostgreSQL；媒体文件放对象存储，不直接塞数据库。

## 12. 非功能需求
### 性能
- 静态资源 CDN 化。
- 图片优先 WebP/AVIF；SVG 用于图标/地图。
- 场景资源按需加载。
- 大资源预加载必须有策略，不能一次加载全部课程。

### 安全
- 密钥只存在服务端环境变量/Secret Manager。
- 前端不得包含 AI API Key、数据库密码等秘密。
- 服务端鉴权和权限校验。
- 上传文件校验 MIME、大小和扩展名。
- 日志避免记录密码、token 和敏感原文。

### 可访问性
- 键盘可操作主要按钮。
- 图标按钮有 aria-label。
- 对比度可读。
- 支持 reduced motion。

### 兼容性
优先 Chrome/Edge 最新稳定版；教学大屏 16:9 为核心目标。

## 13. Demo 不做的内容
为了控制第一版风险，以下不作为 4 小时 Scene01 Demo 的硬要求：
- 真实多租户后台。
- 完整 AI 生成流水线。
- Three.js 大型 3D 世界。
- 实时多人协作。
- 完整学习分析系统。

## 14. 产品化原则
1. 配置驱动优先于页面复制。
2. 模板复用优先于一次性特效。
3. 先完成纵向闭环，再增加模板数量。
4. Demo 代码必须能进入正式架构，不写明显不可维护的临时代码。
5. 课程内容与平台代码分离。
6. 所有关键数据结构版本化。
7. AI 生成必须支持人工审核。

## 15. Demo 成功标准
领导能够在浏览器打开链接，从开场进入至少 2~3 个教学互动场景；视觉表现具有明显区别于 PPT 的沉浸感；团队能够证明更换配置和素材即可复用模板生成第二门课程。

## 16. MVP 成功标准
教师能够创建课程、编辑场景、预览并发布；学生可以打开发布链接完成课程；平台记录基础进度；同一模板能够服务多个课程；AI 可以生成可编辑的课程草稿。
